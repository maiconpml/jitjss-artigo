To validate \texttt{swap\_crit} objectively, we construct a comprehensive algorithmic design space that integrates our operator with established literature components.
Rather than constraining the evaluation to a single manually tuned algorithm, we adopt a bottom-up design space representation \citep{de2018automatic}.
This formulation enables automated algorithm configurators to explore diverse heuristic combinations, testing whether \texttt{swap\_crit} emerges as a preferred operator and drives competitive performance.

Figure~\ref{fig:grammar} formalizes this design space via a context-free grammar in Backus-Naur Form (BNF) \citep{mascia2013grammars}, where derivations from \texttt{<algorithm>} generate valid metaheuristics.
Non-terminals define structural choices, such as initialization (\texttt{<initial\_sol>}), neighborhood selection (\texttt{<neighborhood>}), search strategy (\texttt{<search>}), and scheduling (\texttt{<scheduler>}), whereas terminals specify concrete operators and numeric parameters.

Following the methodology of \citet{mascia2013grammars} and \citet{mascia2014grammar}, we map non-terminal symbols directly to categorical, ordinal, or numerical parameters within an automated configuration framework.
Derivations generate conditional parameter hierarchies, ensuring that the configurator evaluates parameters only when the corresponding algorithmic component is active.
To accommodate recursive structures, such as nested search procedures, within a finite parameter space, we instantiate distinct parameter blocks up to a maximum depth $K$, where decisions at level $i+1$ activate only when the recursive call is instantiated, making level $i+1$ choices conditional on the recursive decision at level $i$.

\subsection{Initialization Rules}
\label{subsec:initialization_rules}

The non-terminal \texttt{<initial\_sol>} derives an initial sequence by pairing a constructive heuristic with a dispatching rule (\texttt{<dispatch\_rule>}).
Available rules include Earliest Due Date (\texttt{edd}), uniform random selection (\texttt{random}), and the composite ALL+CR+SPT rule (\texttt{all\_cr\_spt}) from \citet{wang2014variable}.
The first constructive option, \texttt{priority}, schedules operations sequentially from the schedulable set according to the selected dispatching rule.

The second option, the Giffler--Thompson (\texttt{gt}) algorithm \citep{giffler1960algorithms}, restricts candidate selections to guarantee active schedules before breaking ties via the dispatching rule.
We incorporate GT because it represents the standard constructive baseline across prominent JITJSS works \citep{ahmadian2021meta, abderrazzak2022adaptive, sabri2023reinforcement}.

\subsection{Neighborhood Operators} 
\label{subsec:neighborhood_operators}

The non-terminal \texttt{<neighborhood>} defines seven neighborhood structures partitioned into four groups by their underlying search logic. Each heuristic neighborhood couples with an exploration strategy (\texttt{<improvement>}): First Improvement (\texttt{fi}) or Best Improvement (\texttt{bi}).

The first group comprises classical, unfiltered moves operating on a single machine: \texttt{swap\_adj} swaps adjacent operations \citep{dos2010combination}, while \texttt{swap\_rand} and \texttt{insert\_rand} randomly swap or relocate arbitrary operation pairs \citep{ahmadian2021meta}.

The second group incorporates the penalty-driven heuristics of \citet{wang2014variable}. These operators identify an early (or tardy) operation $u$ and exploit machine idle time by tracking precedence properties. The \texttt{swap\_penal} operator searches upstream or downstream within the same job until finding an operation with an adjacent machine neighbor to swap. Meanwhile, \texttt{insert\_penal} relocates $u$ to the boundary of its contiguous machine block whenever precedence feasibility allows, directly reducing idle gaps without introducing secondary delays.

The third group consists of our proposed \texttt{swap\_crit} operator (Section~\ref{sec:swap_crit}). Unlike localized or intra-job adjustments, \texttt{swap\_crit} traces the disjunctive critical path across multiple jobs and machines, swapping boundary operations of critical blocks to target the structural sources of tardiness directly.

The fourth group contains \texttt{relax}, an exact hybrid operator that re-optimizes a selected sub-sequence of operations via CPLEX within a 1-second limit \citep{ahmadian2021meta}. Because CPLEX solves the sub-problem directly, \texttt{relax} produces a single deterministic move, bypassing the \texttt{<improvement>} parameter.

\subsection{Search Procedures}
\label{subsec:search_procedures}

The non-terminal symbol \texttt{<search>} selects the high-level metaheuristic search framework: Local Search (\texttt{ls}), Tabu Search (\texttt{tabu}), or Iterated Local Search (\texttt{ils}).
Local Search represents a fundamental single-solution search procedure that iteratively explores the solution space using a selected neighborhood structure.
Starting from an initial sequence, the LS procedure evaluates neighbor solutions according to the configured exploration mode and transitions to improving solutions until reaching a local optimum.

Tabu Search (TS) escapes local optima using recency-based memory to prevent cyclic trajectories \citep{talbi}.
The tabu memory records the disjunctive graph arcs broken by recent moves, prohibiting their reversal during a configurable \emph{tabu tenure} (\texttt{tenure}).
For operation swap moves, the algorithm marks the incoming arcs of the swapped operations as tabu, whereas for insert moves, it marks the incoming arc of the relocated operation.
During neighborhood exploration, TS selects candidate moves by priority: (i) the best move satisfying the aspiration criterion (improving the global best); (ii) the best non-tabu move; or (iii) the oldest tabu move when all candidate moves are tabu.
When selecting an expired tabu move, the algorithm advances its internal clock to purge all older entries automatically.

To maintain search diversification and recover from stagnation, TS incorporates an elite solution list $E$ of size $L$ (\texttt{elite\_list\_size}) alongside a non-improvement iteration counter \citep{zubaran2016tabu}.
The elite list $E$ stores solutions that achieve a global objective improvement, retaining their full search states, including unexplored neighborhood branches and the active tabu memory configuration at the time of discovery.
If the search executes a maximum allowed number of consecutive non-improving iterations (\texttt{limit\_iters}), TS initiates a backjump operation to resume exploration from the elite list.

In addition to monitoring non-improving iterations, TS employs a dedicated cycle detector to prevent search trajectory cycling \citep{zubaran2016tabu}.
The cycle detector tracks the objective values across the last $d$ (\texttt{max\_d}) visited solutions.
If this exact sequence repeats $c$ (\texttt{max\_c}) consecutive times, the algorithm triggers an immediate backjump operation.

Upon executing a backjump, the algorithm restores the search state of the most recent elite solution in $E$, reloading its tabu memory state while excluding previously explored neighbor moves from that solution.
Furthermore, each time a backjump occurs, the algorithm dynamically scales the non-improvement iteration limit by a factor of $(1 - 1/x)$, where $x$ corresponds to \texttt{<decrease\_divisor>}.
When all neighborhood branches of the current elite solution are exhausted, TS purges it from $E$ and cascades the backjump to the penultimate elite solution.
Finally, if a backjump is triggered while the elite list $E$ is empty, the Tabu Search procedure terminates.

Iterated Local Search acts as a high-level algorithmic container that repeatedly perturbs the incumbent solution, applies an inner search procedure (LS or TS) to reach a new local optimum, and evaluates the candidate solution using an acceptance criterion \citep{talbi}.
To escape attraction basins during search stagnation, ILS incorporates a dedicated perturbation mechanism based on the state-of-the-art strategy of \citet{ahmadian2021meta}.
This perturbation randomly selects two machines, relaxes the disjunctive precedence constraints across all operations assigned to those two machines, and calls the CPLEX solver with a 1-second time limit to re-optimize their ordering before resuming the inner search.
The outer acceptance criterion is strictly elitist, accepting a candidate solution only if it improves the incumbent global best.

Furthermore, when configured with an ordered sequence of distinct neighborhood structures ($N_1, N_2, \ldots, N_k$), the algorithm advances to the next neighborhood structure whenever an iteration fails to yield a global improvement.
Upon reaching the end of the neighborhood list ($N_k$), ILS loops cyclically back to the first neighborhood ($N_1$) to resume exploration.
This cyclic progression emulates the neighborhood-change step of Variable Neighborhood Search (VNS) \citep{talbi}, allowing the grammar to synthesize both ILS and VNS configurations within a unified grammar structure.

\subsection{Schedulers}
\label{subsec:exact_subsolvers}

Under the non-terminal \texttt{<scheduler>}, the design space provides two timing sub-solvers that determine operation completion times $C_{ik}$ and evaluate the objective penalty $z$ on the fixed acyclic graph $G(\pi)$.

The first option, \texttt{cplex}, formulates the exact timing sub-problem for sequence $\pi$ as a Linear Program (LP), invoking CPLEX to find optimal completion times $C_{ik}^*$.
To mitigate the high computational overhead of invoking an external solver iteratively during search, \texttt{cplex} operates under a strict 1-second time limit per sequence evaluation, returning the best solution available upon timeout.

The second option, \texttt{linear}, is a linear-time heuristic scheduler that combines early scheduling with a right-shifting mechanism.
Initially, \texttt{linear} schedules operations as early as possible along the acyclic graph $G(\pi)$ in linear time with respect to the total number of operations.
A subsequent backward pass shifts early operations into available idle slots without delaying downstream operations, reducing earliness penalties while preserving feasibility and objective monotonicity.
